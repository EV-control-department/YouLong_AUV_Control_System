## 一、hw_manager — 硬件管理节点重写

### 1.1 设计定位

将 hw_manager 从占位节点重写为完整的**硬件管理监控节点**。不参与运动控制数据路径，专注于：

- ✅ 心跳生成 (10Hz `/zit6/cmd/agxhbt`)
- ✅ MCU 状态监控 + 格式化日志
- ✅ INS 启动序列追踪
- ✅ 安全看门狗（心跳超时、电池、错误标志、推力饱和）
- ❌ 不做 PID 控制（MCU 的工作）
- ❌ 不订阅 pos/vel（basic_motion 已做）
- ❌ 不拦截 light/servo（task_runner 直发）
- ❌ **不管理 agent 进程**（经讨论决定移除此功能）

### 1.2 启动序列状态机

```
INIT → WAITING_INS → INS_READY → ARMED → RUNNING
                           ↓                  ↓
                        (持续等待)        DEGRADED
                                         (心跳超时/错误)
```

| 阶段 | 触发条件 | 日志输出 |
|------|---------|---------|
| WAITING_INS | 节点启动 | — |
| INS_READY | `navigation_ready=true` | "INS navigation ready! state=..." |
| ARMED | `is_armed=true` | "MCU ARMED!" |
| RUNNING | `control_level>0` | "MCU RUNNING: control_level=POS/VEL/FORCE" |
| DEGRADED | 心跳/状态超时 | ERROR 日志，继续发心跳等待 MCU 恢复 |

### 1.3 安全看门狗

| 监控项 | 条件 | 级别 | 响应 |
|--------|------|------|------|
| MCU 心跳超时 | `/zit6/state/zithbt` 超 7s 无更新 | ERROR | 日志告警，降级到 DEGRADED |
| 状态丢失 | `/zit6/state/status` 超 7s 无消息 | ERROR | 日志告警 |
| MCU 意外断锁 | `is_armed` true→false | ERROR | 日志告警 |
| 电池低电压 | `battery < 14.0V` | WARN | 30s 节流告警 |
| 错误标志 | `error_flags != 0` | ERROR | 位域解析+日志 |
| 推力饱和 | 任意推力 > 0.95 | WARN | 5s 节流告警 |
| 心跳序号停滞 | seq 不变 | WARN | 10s 节流告警 |

### 1.4 1Hz 状态摘要格式

```
ARM:● RUNNING      | INS:SINS/GPS/DVL  NAV:✓ | CTRL:POS  | BAT:16.2V | CYC:49.8ms | SEQ:1234 | Fx=+1.2 Fz=+0.5
```

### 1.5 关键设计决策

- **不主动停止心跳**：MCU 自带硬件看门狗 (~5s 复位)，hw_manager 只负责报警 + 继续发心跳等待 MCU 复活
- **看门狗超时 7s**：给 MCU 足够的恢复时间，避免误报
- **状态锁 (`threading.Lock`)**：保护 `_mcu_status` 的线程安全访问

### 1.6 hm_launch.py 变更

- **移除** `sim_bridge` 节点启动（`sim_bridge` 在 `uv_sim` 包中，不属于 `uv_hm`）
- **新增** `arm_mode`、`heartbeat_rate`、`watchdog_timeout` 三个可配置 launch 参数
- **保留** `hw_manager` 节点启动

```bash
# 使用示例
ros2 launch uv_hm hm_launch.py arm_mode:=3 watchdog_timeout:=10.0
```

## 二、LineFollower — 参数提取 + 标记处理增强

### 2.1 参数提取到模块级常量

将所有 ~40 个 PID 及配置参数从内联 `params.get()` 提取到模块级常量：

```python
# 横向 PID
_LINE_PID_P = 0.009
_LINE_PID_I = 0.0
_LINE_PID_D = 0.0
_LINE_PID_OUTPUT_LIMIT = 0.30
...

# 偏航 PID
_HEADING_PID_P = 1.5        # 从 0.15 上调
_HEADING_PID_I = 0.005
_HEADING_PID_D = 0.02
_HEADING_PID_OUTPUT_LIMIT = 12.0  # 从 6.0 上调
...

# 前向运动
_FORWARD_STEP = 0.05        # 从 0.10 下调
_MIN_FORWARD_STEP = 0.02
...
```

**加载方式**：`__init__` 中用 `float(params.get('key', _DEFAULT))` 赋值到 `self._*` 属性。tasks.json 可选择性覆盖任意参数。

### 2.2 三角形标记处理增强

对齐后的动作序列变更：

```
旧：下沉 0.5m → 上升 0.5m
新：BMOVE xy (0.1, 0.05) → 下沉 0.7m → 上升 0.7m
```

| 参数 | 旧值 | 新值 | 说明 |
|------|------|------|------|
| `_TRIANGLE_XY_ADJUST_DX` | — | 0.1 | 新增：对准后前移 |
| `_TRIANGLE_XY_ADJUST_DY` | — | 0.05 | 新增：对准后右移 |
| `_TRIANGLE_SINK_DEPTH` | 0.5 | 0.7 | 下沉深度加深 |

### 2.3 标记抑制机制增强

**问题**：旧逻辑仅根据 bbox 在图像中的位置判断是否解除抑制。如果 AUV 在标记上方反复上下运动，可能误触发。

**修复**：抑制解除现在需要同时满足两个条件：

1. **位置条件**：bbox 中心在图像上方 `_MARK_SUPPRESS_UPPER_FRAC`（默认 1/5）区域
2. **距离条件**：AUV 从处理标记时的位置移动了 `_TRIANGLE_MIN_DIST`（默认 0.3m）以上

```python
if (bbox_center_y < height * self._mark_suppress_upper_frac
        and dist > self._triangle_min_dist):
    self._triangle_approached = False
```

新增 `_last_mark_x`、`_last_mark_y` 记录处理标记时的 AUV 位置，用于距离计算。

### 2.4 正方形标记旋转参数化

| 参数 | 旧值 | 新值 | 说明 |
|------|------|------|------|
| `_SQUARE_ROTATION_STEP` | 硬编码 120.0 | 可配置 120.0 | 单次 BMOVE rz 角度 |
| `_SQUARE_ROTATION_COUNT` | 硬编码 3 | 可配置 3 | 旋转次数 |

### 2.5 参数默认值调整

| 参数 | 旧默认值 | 新默认值 | 原因 |
|------|---------|---------|------|
| `forward_step` | 0.10 | 0.05 | 巡线更精细，减少冲出管道 |
| `heading_pid_p` | 0.15 | 1.5 | 提高偏航响应速度 |
| `heading_pid_output_limit` | 6.0 | 12.0 | 允许更大的偏航修正 |
| `max_yaw_step` | 3.0 | 12.0 | 与 output_limit 匹配 |

### 2.6 正方形 LED 闪烁时序修复

```python
# 旧：每次闪灯后只 sleep 0.5s
time.sleep(0.5)
self._node.light_off()
time.sleep(0.5)

# 新：闪灯和关灯后各 sleep 2s，确保在水下可见
time.sleep(2)
self._node.light_off()
time.sleep(2)
```

## 三、task_runner — START 启动前 LED 倒计时

在 `_task_start()` 开头新增 LED 倒计时序列，用于实机拔缆操作：

```
阶段1: LED 3 亮 1s → 灭         "准备启动，请做好拔缆准备"
阶段2: LED 1 闪 1 次 (0.5s)     "AUV 即将发动，请拔缆"
阶段3: LED 2 闪 7 次 (0.25s×7)  "AUV 将在 6 秒后启动"
阶段4: LED 2 亮 1s → 灭         "最后 2 秒警告"
→ 执行 START (初始化 odom 原点)
```

LED 信号含义：
- `set_light(3, 'LED')` — 黄灯：准备阶段
- `set_light(1, 'LED')` — 红灯：等待拔缆
- `set_light(2, 'LED')` — 绿灯：倒计时/启动
