# 目标物静态三维位置估计节点设计

## 1. 文档目的

本文定义 `object_localizer` 节点，用于根据下视双目建立并维护比赛目标的静态位置：

1. 当前机器人位置和姿态；
2. 下视双目的目标识别结果；
3. 下视双目的内参、畸变和左右目外参；

估计每个静态目标物在机器人 `odom/NED` 坐标系中的三维位置，并在机器人移动、从不同位置重复观测同一目标时持续融合更新。

本方案明确**不使用**现有 `workspace_auv/src/uv_camera/uv_camera/position.py` 的定位实现。现有 `position` 节点只作为历史实现保留，新节点需要重新实现并单独验证。

历史的三种观测模型及其误差推导见：[目标物三维位置估计：观测与误差建模](目标物三维位置估计观测与误差建模.md)。当前运行版本已经按新的比赛策略收敛为**只使用下视直接观测**；前视代码保留在文件中用于兼容旧离线测试，但没有订阅、不会执行、不会进入目标轨迹。

## 2. 目标与基本策略

当前核心策略是：

```text
下视左右目检测
        ↓
双目校正、匹配、三角化（或下视平面求交）
        ↓
转到目标时间对应的 odom/NED 坐标
        ↓
按物理类别进入大型下视观测池
        ↓
按 N/E 二维空间做 K 聚类（门 K=4 / 引导线 K=6 / 其他 K=1）
        ↓
每个实例独立的 50 条下视观测卡尔曼队列
        ↓
发布稳定的静态位置、协方差和观测记录
```

当前运行只保留下视直接观测：

- 每条有效下视观测先进入对应物理类别的观测池；
- 观测池中的全部有效观测参与该类别的二维 N/E K 聚类，不因实例数已满而丢弃；
- 每个聚类簇再绑定一个实例，并把簇内最近 50 条观测送入卡尔曼队列；
- 不使用 Z/Down 进行 K 聚类或实例身份判断，Z 只作为簇内滤波的附带分量；
- 每个实例最多保留 50 条下视样本，队列满后按先进先出滑动。

这里的“观测形式”不是目标类别，也不是目标运动状态，而是本次位置测量使用的几何信息类型：

| 观测形式 | 含义 | 典型质量 |
|---|---|---|
| `DOWN_DIRECT` | 下视单次直接定位；优先利用已知池底/目标平面求射线与平面交点，也可用下视左右目单帧三角化 | 通常精度较高，但仍须通过几何和质量检查 |

当前同一静态目标的所有有效下视观测必须合并到同一个 `instance_id`，不能因为左右目或观测时间不同而创建多个目标。

### 2.1 场景实例数量先验

比赛场景中，引导线有 6 个、门有 4 个，其余每种物品只有 1 个。`object_localizer` 因此将它作为数据关联的硬上限：

| 物理语义类别 | 最大实例数 |
|---|---:|
| `guide_line` | 6 |
| `gate` / `door` | 4 |
| 其他类别 | 1 |

类别关联前会删除类别名末尾的 `_down`；例如 `gate_down` 归为 `gate`，`collection_frame_down` 归为 `collection_frame`。单条观测和 GUI 仍保留其原始 YOLO `class_id`，因此可以追溯是哪个识别 ID 给出了证据。

当前只接受下视检测：`xxx_down` 进入下视观测，带 `_front` 的标签和前视检测消息不会被订阅；没有后缀的类别（如 `guide_line`）也只从下视消息进入。这样不会让前视误检污染位置轨迹。

同一类别的下视观测先进入大型观测池，再按该类别的已知数量 K 做二维 N/E 聚类；若初始误检占据了唯一类别的位置，后续正确观测仍会进入同一个池并参与 K=1 的重新估计，不能因在线实例上限而拒绝。不能使用完整 XYZ 欧氏距离做身份判定，因为一次错误视差可能只让 D（深度）跳变，却仍然落在同一个目标的 N/E 投影附近。门 K=4，引导线 K=6，其他类别 K=1。引导线聚类中心之间必须满足 `guide_line_min_spacing_m=0.5 m`，否则近邻簇会合并。上限可通过 `max_instances_default`、`max_instances_guide_line`、`max_instances_gate` 参数调整。

下视每个实例维护最多 50 条完整 XYZ 观测的卡尔曼队列。聚类和簇到实例的对应只使用 N/E；簇内的 N/E/D 三个分量再一起进入窗口滤波。节点还会按类别合并已存在的近邻重复假设：引导线使用 0.5 m 规则距离，其他类别使用 `down_duplicate_merge_distance_m`，保留较小的 `instance_id` 并复制证据更强的滤波状态。

语义类别由 `class_names[class_id]` 得到。当前默认表覆盖工程现有的 `gate_front`、`gate_down`、`guide_line` 等类别，并兼容名称为 `door` 的三类模型；若更换 YOLO 权重且类别顺序不同，必须同时向 `object_localizer` 传入该权重实际的 `class_names`，否则数值 ID 会被解释成错误的物理类别，实例上限也会随之失效。

## 3. 节点边界

### 3.1 新节点

| 项目 | 约定 |
|---|---|
| 节点名 | `object_localizer` |
| 作用 | 下视双目目标三维观测生成、类别观测池、实例关联和卡尔曼队列融合 |
| 是否订阅图像 | 否。目标检测由视觉节点完成，本节点只订阅检测元数据 |
| 是否使用旧 `position` | 否 |
| 推荐输出坐标系 | `odom`，轴向采用 NED：North、East、Down |
| 推荐输出频率 | 10 Hz |

### 3.2 输入话题

| 话题 | 类型 | 用途 |
|---|---|---|
| `/basic_motion/pose_info` | `uv_msgs/msg/PoseInfo` | 机器人位置、roll/pitch/yaw 以及时间戳 |
| `/perception/detection/down_left` | `uv_msgs/msg/DetectionArray` | 下视左目检测 |
| `/perception/detection/down_right` | `uv_msgs/msg/DetectionArray` | 下视右目检测 |

`DetectionArray.header.stamp` 是图像/检测对应的时间；不能使用检测消息到达时的当前位姿替代它。节点必须用该时间在位姿缓存中查找或插值得到机器人在拍摄时的姿态。

`Detection` 当前包含：`class_id`、`confidence`、框中心 `(pixel_x, pixel_y)` 和边界框四角。第一版使用框中心作为目标观测点，并保留按类别配置锚点的能力：

下视观测必须由左右目消息按时间戳配对，并通过同类目标一对一匹配、极线/视差、正深度和重投影检查；启用下视平面模式时，还必须通过左右目平面交点一致性检查。任何通过几何质量检查的下视点都会先进入按类别的大型观测池；池中观测再通过二维 N/E K 聚类决定所属实例和队列，不会因为旧实例已经达到数量上限而直接丢弃。

| 类别 | 默认观测点 |
|---|---|
| 球体 | 边界框中心，近似球心 |
| 门/框体 | 边界框中心；后续如控制需要，可切换为门中心或指定接触点 |

### 3.3 输出话题

现有 `ObjectPosition` 只有位置、置信度和观测数量，不能表达协方差、观测形式和静态位置状态。新节点目前发布一个带完整状态的主题，同时保留兼容旧任务节点的主题：

| 话题 | 推荐类型 | 用途 |
|---|---|---|
| `/perception/target_positions` | `uv_msgs/msg/TargetPositionArray` | 对外发布静态目标位置、协方差和观测来源 |
| `/perception/objects` | `uv_msgs/msg/ObjectPositionArray` | 兼容 `TaskRunner`/旧下游的静态目标位置 |
| `/perception/target_observations` | `uv_msgs/msg/TargetObservationArray` | 最近的有效下视直接三维测量点，供 GUI 和回放诊断使用 |
| `/perception/target_localizer/status` | 暂未实现 | 后续发布同步、标定和融合诊断 |

`TargetPosition` 至少需要包含：

```text
class_id / class_name
physical_class_name          # 去掉 _down 后的物理类别
observed_class_ids           # 本轨迹实际接受过的原始 YOLO ID
instance_id
position_odom_x / position_odom_y / position_odom_z
position_covariance[9]
confidence
observation_form_mask    # 当前实现固定为 DOWN_DIRECT=4
last_update_form         # 仅调试：最近一次更新使用的观测形式
status                   # UNINITIALIZED / ESTIMATING / STABLE / STALE
age_sec
last_observation_stamp
observation_count
front_stereo_count
front_multi_view_count
down_direct_count
```

当前运行中 `observation_form_mask` 应为 `DOWN_DIRECT=4`；它仍表示历史上哪些下视直接观测参与过该目标位置估计。`last_update_form` 只用于回放和诊断。

`/perception/target_observations` 的单条消息与融合后的 `TargetPosition` 有意区分：当前每条下视观测包含独立的三维测量点及其测量协方差；观测先进入类别池，再进入某个实例的卡尔曼队列。每条观测同时保留原始 `class_id/class_name` 和绑定后的 `physical_class_name`。GUI 以 `physical_class_name/instance_id` 聚合显示，并展示原始标签以追溯证据，详见：[目标位置可视化 GUI](目标位置可视化GUI.md)。

输出中的位置必须明确是 `odom/NED` 坐标，不能把相机坐标、机体坐标或仿真器原始 `map` 坐标混在一起。

## 4. 坐标系和时间约定

### 4.1 坐标系

| 坐标系 | 轴定义 | 用途 |
|---|---|---|
| `odom/NED` | x=North，y=East，z=Down | 机器人位姿和目标最终输出 |
| `body/FRD` | x=Forward，y=Right，z=Down | 机器人机体坐标 |
| `camera_optical` | x=Right，y=Down，z=Forward | OpenCV 相机坐标 |
| `camera_rectified` | 由 `R1/R2` 定义的校正相机坐标 | 双目三角化坐标 |

`PoseInfo.robot_x/y/z` 是机器人在 `odom` 中的位置，`robot_roll/pitch/yaw` 使用度。新节点必须实现完整的 roll、pitch、yaw 旋转，不能只使用 yaw。

仿真中不得把 Stonefish 场景原始坐标直接作为 `odom/NED` 发布。当前比赛场景的俯视朝向是 Stonefish `+Y` 指向北、Stonefish `-X` 指向东，因此 `sim_bridge` 在设定出生点为原点后统一转换：`N = Δscene_y`、`E = -Δscene_x`、`D = Δscene_z`，并使用 `yaw_NED = wrap(yaw_scene - 90°)`。这保证 `/zit6/state/pos`、`/basic_motion/pose_info`、`/perception/target_positions` 与 GUI 使用同一坐标；定位器本身不再额外旋转观测结果。

### 4.2 位姿时间对齐

节点维护至少 3 秒的位姿缓存。对每个检测时间 `t_det`：

1. 优先在相邻两帧位姿之间对位置线性插值；
2. 姿态使用四元数插值，或在角度变化很小时对 roll/pitch/yaw 插值；
3. yaw 插值必须处理 ±180° 跨越；
4. 若最近位姿与检测时间差超过 `pose_max_age_ms`，丢弃该观测或标记为无效；
5. 禁止用“最新收到的位姿”直接处理带历史时间戳的图像。

位姿变换关系为：

```text
p_odom = p_robot_odom
        + R_odom_body(pose) · t_body_camera
        + R_odom_body(pose) · R_body_camera · p_camera
```

其中 `p_camera` 是双目三角化得到的点，`t_body_camera` 和 `R_body_camera` 必须来自当前标定配置，而不是散落在代码中的经验常数。

## 5. 双目标定数据

### 5.1 运行 profile 与标定来源

`object_localizer` 有两个互斥的标定来源，由 `calibration_source` 明确选择：

| 运行 profile | `calibration_source` | 内参来源 | 左右目相对外参来源 |
|---|---|---|---|
| 实机/录包 | `npz`（默认） | `down.npz` | 下视 npz 中的 `R/T/R1/R2/P1/P2` |
| 默认 Stonefish 仿真 | `sim_camera_info` | Stonefish 正在发布的下视两路 `CameraInfo` | 当前 `xunyun_fixed.scn` 的下视相机 `<origin>` |

`sim_bringup.py` 已为定位器选择 `sim_camera_info`；因此仿真中的下视双目三角化**不会读取** `.npz`，也不会订阅或处理前视数据。实机 `real_bringup.py` 使用默认 `npz` profile，但定位器仍只加载 `down.npz`。

Stonefish 的 `CameraInfo` 由仿真器在每帧图像同时发布，节点订阅：

```text
/sim/down_cam/left/camera_info
/sim/down_cam/right/camera_info
```

它的生成逻辑是 `fx=cx/tan(hfov/2)`、`fy=cy/tan(vfov/2)`，并发布零畸变 `D=[0,0,0,0,0]`。当前默认场景的实际数值为：

| 相机对 | 分辨率 | 水平 FOV | K（左右相同） | D | 基线 |
|---|---:|---:|---|---|---:|
| 下视 | 1280×960 | 87.19° | `fx=fy=672.183656, cx=640, cy=480` | 0 | 0.100 m |

四个相机相对于 `Vehicle`（同时也是 `/auv/odometry` 的原点）的实际位置为：前左/右 `(0.23, -/+0.05, 0.276) m`，下左/右 `(-0.13, -/+0.05, 0.2645) m`。节点收到每对 CameraInfo 后，以这些相机外参计算左右目的 `R/T`，再用 `cv2.stereoRectify` 生成此运行时 profile 的 `R1/R2/P1/P2/Q`；不会把实物标定文件内的基线套到仿真图像上。

### 5.2 实机标定文件

仓库当前有：

- `workspace_auv/src/uv_camera/config/front.npz`
- `workspace_auv/src/uv_camera/config/down.npz`

每个文件包含：

```text
camera_matrix_left/right
dist_coeffs_left/right
R, T
R1, R2
P1, P2
Q
```

新节点应从标定文件加载这些数据。不能使用 `common.py` 中的近似焦距和零畸变参数替代标定文件，也不能使用旧 `position.py` 中的相机参数。

当前决定：`down.npz` 保持现状，作为下视相机的标定 profile 直接加载使用；不根据产品规格图改写该文件。产品规格只能作为硬件参考，不能替代标定矩阵。

### 5.4 标定 profile 的使用方式

对左右目检测中心 `u_left`、`u_right`，无论 profile 来自实机 npz 还是仿真 CameraInfo：

1. 使用左右目各自的 `K`、`D` 和 `R1/R2` 调用 `cv2.undistortPoints`；
2. 使用校正后的像素和 `P1/P2` 调用 `cv2.triangulatePoints`；
3. 齐次坐标除以最后一维得到 `p_camera_rectified`；
4. 用左目校正坐标系对应的 `T_body_camera_rectified` 转到机体坐标；
5. 再使用拍摄时刻的机器人姿态转到 `odom/NED`。

不要直接把 `Q`、`T`、`P1/P2` 混合使用而不检查坐标系。第一版以 `P1/P2` 三角化为主，`Q` 仅用于交叉验证。

### 5.5 标定一致性检查（必须在节点启动时执行）

启动时必须检查：

- 左右目图像尺寸与标定尺寸一致；若图像被缩放，K、主点和畸变必须同步缩放；
- `P1/P2` 的投影矩阵形状正确，三角化后目标深度为正；
- 左右目校正后的极线垂直残差在阈值内；
- 标定单位为米，或在加载时显式完成单位转换；
- `T` 的单位和方向与 `P2` 推导出的基线一致；
- 机体到相机的外参与仿真场景/实机安装一致。

实机 npz 文件当前仍存在需要单独处理的风险（不影响 `sim_bringup` 的 CameraInfo profile）：

- `front.npz` 由 `P2` 推导的基线约为 `0.05653 m`，`down.npz` 约为 `0.07531 m`；
- 两个文件的原始 `T` 范数分别约为 `1275.57` 和 `1281.13`，与上述米制基线不一致，疑似存在毫米/其他单位或文件来源不一致问题；
- `common.py` 当前使用的焦距约为前视 2158.4、下视 2307.6，并且畸变为 0，与 `.npz` 内参不一致；
- `common.py` 的前视实机采集分辨率为 1280×720，而 `.npz` 按 1280×960 标定，不能直接混用；
- `xunyun_fixed.scn`、其他场景文件和实机的相机安装外参必须分别确认，不能用一个场景的外参覆盖所有模式。

在这些检查未通过时，节点应进入 `CALIBRATION_INVALID` 状态，不得发布看似有效的三维坐标。

## 6. 第一步：单次观测生成

### 6.1 左右目检测同步

前视和下视各自维护一个左右目检测缓存。对于需要双目三角化的观测，只有满足以下条件才组成双目帧：

- `class_id` 可匹配；
- 左右目时间戳差不超过 `stereo_sync_slop_ms`；
- 每个目标在左右目最多匹配一次；
- 匹配后通过极线和三角化质量检查。

当前视觉节点通常对同一拼接帧发布左右目结果，因此优先使用相同 `header.stamp` 配对；实机若左右目独立采集，则必须使用时间容差配对，不能按消息到达顺序硬配。

### 6.2 左右目标匹配

匹配代价按以下顺序构造：

1. 类别必须相同；
2. 去畸变/校正后的垂直坐标差 `|y_left - y_right|` 小于极线阈值；
3. 视差方向和三角化后的深度必须满足正深度约束；
4. 置信度、框尺寸和水平位置差用于处理同类多目标；
5. 多目标场景使用一对一最小代价分配，不能只取置信度最高的一对。

不要假设视差一定为正。视差方向必须由当前 `P1/P2` 和校正坐标系验证；仅当三角化结果满足左右目都在相机前方时才接受。

### 6.3 `FRONT_STEREO` 三角化与质量

每个有效前视左右目检测生成一个 `StereoObservation`，观测形式标记为 `FRONT_STEREO`：

```text
class_id
observation_form         # FRONT_STEREO
stamp
pixel_left/right
point_camera_rectified
point_body
point_odom
reprojection_error_px
epipolar_error_px
depth_m
confidence
measurement_covariance
```

必须拒绝：

- 深度小于等于 0；
- 深度超出配置范围；
- 极线误差过大；
- 重投影误差过大；
- 视差过小导致深度不稳定；
- 标定或位姿时间对齐无效的观测。

深度误差随距离快速放大，近似关系为：

```text
Z = fx * baseline / disparity
σZ ≈ fx * baseline * σdisparity / disparity²
```

因此每个双目观测必须生成协方差，而不是只生成一个没有质量信息的坐标。检测置信度、极线误差、重投影误差和视差大小都应参与协方差计算。

### 6.4 `DOWN_DIRECT` 下视直接定位

`DOWN_DIRECT` 不依赖前视，也不依赖机器人跨位置运动。它表示下视在当前时刻直接看到目标后，利用下视几何约束立即给出位置：

1. 若目标已知位于池底/任务平面，使用下视像素反投影射线与该平面求交；
2. 若没有可用的平面约束，则使用下视左右目单帧三角化；
3. 若左右目无法配对且没有已知平面，不能仅凭单目“看到了”就输出三维位置；
4. 若左右目都能看到目标，可将左右目结果互相校验，但该观测仍属于 `DOWN_DIRECT`，不应与前视多位置混为一类。

平面求交公式为：

```text
d_odom = R_odom_body · R_body_camera · d_camera
p_odom = o_camera_odom + λ · d_odom
λ = (z_plane - o_camera_odom.z) / d_odom.z
```

平面高度、法向、目标锚点和允许的入射角必须是配置项。平面残差、入射角、检测置信度和左右目一致性共同决定 `DOWN_DIRECT` 的协方差。

## 7. 第二步：前视多位置与静态位置融合

### 7.1 静态目标位置状态

目标默认是静态目标，不建立速度状态，只维护三维位置和位置协方差：

```text
p = [px, py, pz]ᵀ
P = position covariance (3×3)
```

位置估计在 `odom` 中维护。机器人运动不会直接修改目标位置；机器人运动只影响每次新观测从相机坐标到 `odom` 的变换。因子图直接优化静态位置；若使用 EKF，静态模型的预测为：

```text
pₖ⁻ = pₖ₋₁
Pₖ⁻ = Pₖ₋₁ + Q_static · Δt
```

`Q_static` 只用于 EKF 表示长时间没有观测时的不确定性增长，不代表目标真的在运动；因子图不需要把它解释为目标速度。

每个目标实例至少保存：

- `class_id`、`instance_id`；
- 当前三维位置和 3×3 协方差；
- 最近观测时间；
- 三种观测形式的计数；
- 观测证据形式和最近一次更新形式；
- 各观测形式的质量摘要和最近一次优化时间；
- 连续丢失时间和位置估计状态。

### 7.2 `FRONT_MULTI_VIEW` 前视多位置观测

`FRONT_MULTI_VIEW` 专门表示前视在不同机器人位置对同一目标的多次观测。它不是多次结果取平均，而是：

1. 将每次前视检测按其时间戳转换为 `odom` 中的观测射线；
2. 通过机器人位置/姿态变化获得不同射线的几何约束；
3. 使用至少两条具有足够夹角的有效射线，通过加权最小二乘或 RANSAC 求目标位置；
4. 根据射线夹角、机器人位姿协方差和残差计算位置协方差；
5. 若已有 `FRONT_STEREO` 位置，则将多位置解作为同一目标的额外测量，而不是创建新目标。

只有机器人产生了足够的有效基线，并且多条射线对同一 `instance_id` 的关联通过门限，才能标记为 `FRONT_MULTI_VIEW`。实现中每个目标最多保留 20 条射线：首条射线建立候选，之后的新射线必须与队列中夹角最近的一条仍**大于 5°**（参数 `front_multi_view_min_angle_deg`），才会入队并参与融合。位姿变化太小、射线接近平行或关联不确定时，只保留候选，不发布高可信的多位置结果。

### 7.3 跨时刻目标实例关联

新观测与已有目标实例的匹配条件：

1. `class_id` 相同；
2. 使用静态位置预测得到当前时刻的位置；
3. 观测位置残差通过马氏距离门限；
4. 同类多目标使用全局一对一分配；
5. 没有匹配目标实例时创建新的 tentative 位置估计。

不能使用“类别 + 相机方向”作为唯一目标键。前视和下视看到的是同一个物体时，必须通过 `odom` 中的静态位置合并到同一 `instance_id`。

### 7.4 三种观测的测量模型与误差

三种观测都针对同一个静态目标位置变量 `Lᵢ`，区别只在观测函数 `hₖ` 和误差协方差 `Rₖ`：

| 观测形式 | 原始测量 | 观测函数 | 是否需要跨位置 |
|---|---|---|---:|
| `FRONT_STEREO` | 前视左右目像素 `(u_l,v_l,u_r,v_r)` | 目标位置投影到前视左右目后的像素残差 | 否 |
| `FRONT_MULTI_VIEW` | 不同时间的前视像素 `(u_k,v_k)` 或射线 | 目标位置投影到各个历史前视位姿后的像素/射线残差 | 是 |
| `DOWN_DIRECT` | 下视像素 `(u,v)`，以及池底/目标平面约束；也可附带下视左右目像素 | 下视射线与目标平面交点残差，或下视单帧双目重投影残差 | 否 |

优先在因子图中保留原始像素观测做重投影，而不是先把所有观测压成一个没有来源信息的三维点。三角化点可以用于初始化、数据关联和质量检查。

#### `FRONT_STEREO`

对同一时刻的前视左右目检测，使用前视标定的 `K_l/D_l`、`K_r/D_r`、`R1/R2/P1/P2`：

```text
z_fs = [u_l, v_l, u_r, v_r]ᵀ
h_fs(Lᵢ, T_odom_camera(t)) =
    [project_left(Lᵢ), project_right(Lᵢ)]ᵀ
r_fs = z_fs - h_fs
```

其中 `T_odom_camera(t)` 使用检测时间对应的机器人位姿和相机外参。双目三角化结果必须满足正深度、极线误差和重投影误差门限。

前视双目的像素误差可以先建模为：

```text
R_pixel_fs = diag(σ²_ul, σ²_vl, σ²_ur, σ²_vr)
```

再把相机标定误差和机器人位姿误差传播到残差中：

```text
R_fs = R_pixel_fs
     + J_calib Σ_calib J_calibᵀ
     + J_pose  Σ_pose  J_poseᵀ
```

远距离、小视差时，三维深度方向的信息天然变弱；如果使用三角化点作为等效位置测量，应通过三角化雅可比传播得到更大的深度方差，不能仍使用固定的 XYZ 方差。

#### `FRONT_MULTI_VIEW`

该观测形式使用前视在不同机器人位置的观测。每条观测都保留自己的时间戳和位姿：

```text
z_mv,k = [u_k, v_k]ᵀ
h_mv,k(Lᵢ, T_odom_camera(t_k)) = project_front(Lᵢ)
r_mv,k = z_mv,k - h_mv,k
```

多位置不是把像素坐标做平均，而是将多个时间点的像素约束同时作用于同一个 `Lᵢ`。如果只保留射线，也可以使用点到射线的正交残差：

```text
o_k = ray origin in odom
d_k = ray direction in odom
r_ray,k = (I - d_k d_kᵀ) · (Lᵢ - o_k)
```

`FRONT_MULTI_VIEW` 的误差主要来自：

- 像素检测中心误差；
- 图像时间与 `PoseInfo` 的时间对齐误差；
- 机器人位置/姿态误差及随时间累积的 odom 漂移；
- 相机外参误差；
- 同类目标跨帧关联错误。

其协方差应写成：

```text
R_mv,k = R_pixel,k
       + J_pose,k  Σ_pose,k  J_pose,kᵀ
       + J_extr,k  Σ_extr    J_extr,kᵀ
```

多条射线的几何质量由联合信息矩阵/因子图 Hessian 体现。射线夹角小、机器人运动基线不足或位姿不确定性过大时，位置协方差会变大；条件数超限时拒绝该多位置解。相邻帧的 odom 漂移可能相关，不能盲目把每一帧当成完全独立的高精度测量。

#### `DOWN_DIRECT`

下视直接观测不依赖前视或跨位置运动。对于位于已知池底/目标平面的目标，使用下视像素反投影射线与平面求交：

```text
z_down = [u, v]ᵀ
d_odom = R_odom_camera · undistort_ray(u, v)
p_down = o_camera_odom + λ d_odom
λ = (z_plane - o_camera_odom.z) / d_odom.z
r_down = p_down - Lᵢ
```

其中 `down.npz` 用于去畸变和下视双目校正；池底/目标平面的高度、法向和不确定性由运行 profile 提供。如果没有可靠的平面约束，则不能仅凭单目下视“看到了”得到三维位置，应改用下视左右目单帧三角化，并将该测量仍标记为 `DOWN_DIRECT`。

下视直接观测的误差传播为：

```text
R_down = J_pixel  Σ_pixel  J_pixelᵀ
       + J_pose   Σ_pose   J_poseᵀ
       + J_plane  Σ_plane  J_planeᵀ
       + J_extr   Σ_extr   J_extrᵀ
```

平面已知且相机俯视角度合适时，`R_down` 通常小于前视观测；但平面高度、相机安装角或目标锚点不确定时，必须把这些误差加入，不能固定认为下视绝对正确。

### 7.5 融合器选型：滑动窗口因子图为主

三种观测没有固定先后顺序，且前视多位置观测可能在下视观测之前或之后到达，因此主方案采用静态目标滑动窗口因子图。因子图的变量为目标位置，观测因子按时间戳加入；测量到达顺序不改变其物理含义。

对每个静态目标实例 `i`，核心变量为：

```text
Lᵢ = [xᵢ, yᵢ, zᵢ]ᵀ       # 目标在 odom/NED 中的静态位置
```

每条观测形成一个因子：

| 因子 | 观测模型 | 误差来源 |
|---|---|---|
| `FRONT_STEREO` | 左右目像素经过标定模型投影到目标位置，或使用三角化点的位置残差 | 视差、检测框、标定、机器人位姿 |
| `FRONT_MULTI_VIEW` | 不同机器人位姿下的前视射线/像素重投影残差 | 观测基线、位姿、像素和目标关联 |
| `DOWN_DIRECT` | 下视射线与目标平面交点，或下视单帧双目重投影残差 | 平面模型、入射角、像素、标定和位姿 |

建议的鲁棒目标函数为：

```text
min_{Lᵢ}  Σₖ ρₖ( rₖ(Lᵢ)ᵀ Rₖ⁻¹ rₖ(Lᵢ) )
```

其中 `Rₖ` 是第 k 条观测自己的协方差，`ρₖ` 使用 Huber/Cauchy 等鲁棒核函数。`FRONT_STEREO`、`FRONT_MULTI_VIEW`、`DOWN_DIRECT` 仅通过各自的 `rₖ` 和 `Rₖ` 区分，不通过顺序或硬切换区分。

因子图实现要求：

- 新观测按时间戳加入，不依赖消息到达顺序；
- 支持同一目标的三种因子同时存在；
- 支持删除超时观测和滑动窗口重优化；
- 输出最优位置和边缘协方差；
- 对单个错误匹配使用鲁棒核或开关因子，不能污染整个目标位置；
- 若使用 `PoseInfo` 作为固定输入，必须把位姿不确定性折算进 `Rₖ`；后续可把位姿修正量作为因子图变量。

如果部署环境暂时不适合因子图，可使用同样的观测模型实现 3D 扩展卡尔曼滤波：状态仅为 `p=[x,y,z]ᵀ`，每种观测使用自己的 `hₖ(p)`、雅可比 `Hₖ` 和 `Rₖ`。EKF 是实时简化实现，不改变三种观测并列、异步、按协方差融合的设计；不得退化成固定比例 EMA 或“下视强制覆盖”。

## 8. 第三步：三种观测形式的无序融合

### 8.1 观测质量建模

每次测量必须记录 `observation_form`，不能只记录“来自前视/下视”。三种观测的差异体现在观测函数和协方差，而不是处理顺序：

| 观测形式 | 是否依赖左右目 | 是否依赖机器人跨位置运动 | 主要质量因素 |
|---|---:|---:|---|
| `FRONT_STEREO` | 是 | 否 | 视差、左右目匹配、重投影误差、标定 |
| `FRONT_MULTI_VIEW` | 可选；核心是多位置射线 | 是 | 位姿误差、运动基线、射线夹角、跨帧关联 |
| `DOWN_DIRECT` | 可选；可用平面交点或下视双目 | 否 | 池底/目标平面、入射角、检测像素、标定 |

初始协方差只表达测量质量，不表达“谁先到”：

| 观测形式 | 初始协方差策略 |
|---|---|
| `FRONT_STEREO` | 使用双目三角化协方差；远距离小视差时显著增大深度方向方差 |
| `FRONT_MULTI_VIEW` | 使用多视角解的协方差；位姿不稳定、基线不足或射线接近平行时增大或拒绝 |
| `DOWN_DIRECT` | 通过平面/双目几何检查后使用较小协方差；平面不确定性必须计入协方差 |

“下视通常更准”应体现为 `DOWN_DIRECT` 的 `Rₖ` 通常更小，而不是无条件覆盖前视结果。若某次下视平面参数、标定或匹配异常，它可以被因子图的残差门控和鲁棒核函数降低权重或拒绝。

### 8.2 无序观测的融合流程

对于每一条有效观测：

1. 按观测时间查找机器人位姿，并转换到 `odom/NED`；
2. 根据类别、空间门限和已有静态位置把观测关联到 `instance_id`；
3. 生成对应观测因子、协方差和质量信息；
4. 把因子加入该目标的滑动窗口并执行增量优化；
5. 输出优化后的位置、协方差和观测形式掩码。

观测可以采用任意顺序：

```text
FRONT_STEREO → DOWN_DIRECT → FRONT_MULTI_VIEW
FRONT_MULTI_VIEW → FRONT_STEREO → DOWN_DIRECT
DOWN_DIRECT → FRONT_STEREO → FRONT_MULTI_VIEW
```

只要时间戳、位姿、标定和数据关联正确，三种顺序都应收敛到相近的静态目标位置。消息到达顺序不能用来决定谁覆盖谁。

位置估计状态只描述当前解的质量，不描述观测先后：

| 状态 | 含义 |
|---|---|
| `UNINITIALIZED` | 尚无有效三维观测 |
| `ESTIMATING` | 已有有效观测，但协方差或几何约束仍较大 |
| `STABLE` | 残差、协方差和观测一致性达到稳定门限 |
| `STALE` | 超过超时时间没有新的有效观测 |

同一个 `instance_id` 可以在任意时刻由三种观测形式共同贡献；`observation_form_mask` 和各计数用于说明证据构成，不能作为滤波优先级。

## 9. 推荐参数

以下是实现初期的参数名和建议范围，最终值必须通过实测/仿真标定，不应写死在算法代码中：

| 参数 | 建议初值/范围 | 说明 |
|---|---|---|
| `front_calibration_file` | `config/front.npz` | 前视双目标定 |
| `down_calibration_file` | `config/down.npz` | 下视双目标定 |
| `stereo_sync_slop_ms` | 10–30 ms | 左右目时间配对容差 |
| `pose_max_age_ms` | 30–80 ms | 检测与位姿允许的最大时间差 |
| `epipolar_error_px` | 2–4 px | 校正后极线误差门限 |
| `reprojection_error_px` | 3–5 px | 三角化重投影误差门限 |
| `min_disparity_px` | 由目标距离和标定决定 | 视差过小则拒绝或增大协方差 |
| `front_stereo_noise_scale` | 2–5 | 前视单帧双目测量噪声放大系数 |
| `front_multi_view_noise_scale` | 1–3 | 前视多位置解的测量噪声放大系数 |
| `down_direct_noise_scale` | 1–2 | 下视直接观测的测量噪声放大系数 |
| `down_observation_pool_size` | 2000 | 每个物理类别的大型下视原始观测池容量 |
| `down_direct_queue_size` | 50 | 每个实例保留的下视 XYZ 卡尔曼观测数 |
| `down_direct_queue_gate_chi2` | 16 | 兼容旧逐实例门控接口；当前池化 K 聚类路径不以 Z 做门控 |
| `guide_line_min_spacing_m` | 0.5 | 引导线实例在 N/E 平面的最小间距 |
| `down_duplicate_merge_distance_m` | 0.25 | 非引导线下视重复实例的 N/E 合并距离 |
| `target_timeout_sec` | 0.5–2.0 s | 目标位置进入 STALE 的时间 |
| `publish_rate_hz` | 10 Hz | 输出频率 |

配置中还必须包含每个相机的 `T_body_camera`，以及每类目标的观测锚点定义。真实相机与仿真相机应使用不同配置 profile，禁止通过代码分支隐式切换。

## 10. 实现顺序

### 阶段 0：标定和坐标验证

- 明确 `front.npz/down.npz` 的长度单位；
- 解决 `T` 与 `P2` 基线不一致问题；
- 确认前/下视实际输入分辨率；
- 将相机安装外参写入 profile；
- 用已知点验证相机坐标到 `body/FRD`、`odom/NED` 的方向和正负号。

### 阶段 1：单次观测定位

- 左右目同步；
- 去畸变和立体校正；
- 同类目标一对一匹配；
- 三角化和重投影质量检查；
- 发布 `TargetObservationArray`，暂不做长期静态位置融合。

### 阶段 2：跨位置静态位置融合

- 接入带时间戳的 `PoseInfo` 缓存；
- 每个观测变换到 `odom/NED`；
- 同类多目标的目标实例关联；
- 静态位置模型和协方差滤波；
- 发布 `TargetPositionArray`。

### 阶段 3：三种观测形式策略

- 实现滑动窗口因子图；资源受限时使用同一观测模型实现扩展卡尔曼滤波；
- 将 `FRONT_STEREO`、`FRONT_MULTI_VIEW`、`DOWN_DIRECT` 作为并列因子按时间戳加入；
- 用观测质量、协方差和残差判断位置是否稳定，不用观测先后决定状态；
- 增加观测顺序置换测试和不同观测形式之间的位置冲突诊断；

## 11. 验收标准

### 双目

- 已知静态目标在相机有效范围内，三角化深度为正；
- 左右目检测顺序变化不会导致错误配对；
- 目标远离相机、视差变小时，协方差增大而不是输出虚假的高精度；
- 标定文件无效、尺寸不符或单位不一致时不发布有效目标坐标。

### 位姿和坐标

- 机器人只改变位置时，静态目标的 `odom` 坐标保持稳定；
- 机器人只改变 yaw/pitch/roll 时，目标坐标变换方向正确；
- 检测与位姿时间错开时，使用检测时间对应的位姿，而不是回调时最新位姿。

### 融合

- 任意一种有效观测形式都可以初始化目标位置；
- 三种观测形式按任意顺序输入，最终位置应收敛到相近结果；
- `DOWN_DIRECT` 通常具有更小协方差，但不能无条件覆盖其他有效观测；
- 错误观测经过马氏距离门控和鲁棒核函数后不能明显拉偏目标位置；
- 长时间没有有效观测时，位置状态进入 `STALE`；
- 同类多个目标不会因观测形式切换产生重复目标位置估计。

## 12. 当前必须保留的注意事项

- 新节点不能导入或调用旧 `position.py` 的定位函数、相机参数、类别映射或内存结构；
- `class_id → class_name` 必须来自当前模型/数据集配置。若使用 8029 数据集，应遵循 `docs/比赛规则/国水2026/yolo_id_table.md` 的类别定义，不在定位节点中另写一套映射；
- 仿真场景中的相机位姿不是实机标定结果，必须按运行 profile 加载；
- 所有位置、姿态、观测和融合结果都必须保留时间戳，便于录包回放和误差分析；
- 调试时优先查看 `TargetObservationArray` 的观测形式、极线误差、重投影误差、视差、深度和协方差，不要只看最终坐标。
