\section{启动组织}
启动文件只负责编排节点、声明参数、选择 profile、建立 remap 和处理关键进程退出；算法状态和业务逻辑留在节点实现中。真机启动由 \pkg{uv_bringup} 管理，仿真启动由 \pkg{uv_sim_bringup} 管理。

\section{整机启动 Profile}
\code{profile} 只表示整机启动模式，由 \pkg{uv_bringup} 和
\pkg{uv_sim_bringup} 的顶层 launch 提供。它不是传给节点的 ROS 2 参数文件：
对应 YAML 位于 \code{config/profiles/<runtime>/}，用 \code{runtime} 和
\code{profile} 标识运行环境与模式，并在 \code{arguments} 中设置 launch
参数默认值。命令行显式给出的参数优先。真机与仿真/HIL 分别维护自己的
profile 文件，启动器会校验运行环境，避免跨环境加载。

真机 \pkg{uv_bringup} 提供 \code{default}、\code{record}、\code{debug} 和
\code{task} 四种 profile。四种模式默认都关闭尚未完成的路径跟随导航；
需要时可以显式传入 \code{enable_nav:=true}。
\begin{itemize}
  \item \code{default} 保持基本启动组合：启用硬件、AI、运动和视频流，不启动任务、不录制，并关闭导航。
  \item \code{record} 关闭 AI、导航和任务，保留运动控制，启动 raw 源图像、rosbag 与 session 日志录制，不启动 go2rtc。
  \item \code{debug} 启用 AI、运动和 go2rtc/session 录制，不自动启动任务，关闭导航。
  \item \code{task} 启用 AI、运动、任务执行和 go2rtc/session 录制；任务 runner 默认加载
        \code{robocup_26.yaml} 并开始完整 Mission。导航仍默认关闭；需要导航时显式设置
        \code{enable_nav:=true}。
\end{itemize}

\pkg{uv_sim_bringup} 的 sim 与 hil 各自提供同名的四种 profile，保留各自已有的
启动组合。公开场景入口 \pkg{uv_sim} 使用 \code{world} 选择 Stonefish 场景；
场景选择与 bringup 的 \code{profile} 相互独立。

组件节点使用所属包的默认参数。需要替换节点参数文件时，组件 launch 通过
\code{params_file} 接收 ROS 2 参数 YAML；相机标定文件位于
\code{uv_camera/stereos/}，其 \code{modes.real} 与 \code{modes.sim} 保存两种
相机运行模式的数据，不属于整机启动 profile。

\section{常用启动命令}
\begin{lstlisting}[language=bash,caption={标准运行入口}]
# Real
cd workspace_auv
colcon build --symlink-install
source install/setup.bash
ros2 launch uv_bringup real.launch.py profile:=default

# SIL
cd workspace_sim
colcon build
source install/setup.bash
ros2 launch uv_sim_bringup sim.launch.py profile:=debug

# 公开场景入口通过 world 选择场景
ros2 launch uv_sim sim.launch.py world:=sauvc_2026/finals

# HIL
ros2 launch uv_sim_bringup hil.launch.py profile:=default \
  serial_dev:=/dev/ttyUSB0 serial_baud:=921600
\end{lstlisting}

\begin{lstlisting}[language=bash,caption={按整机启动 profile 选择运行模式}]
# 数据集采集：uv_record raw 源帧
ros2 launch uv_bringup real.launch.py profile:=record
ros2 launch uv_sim_bringup sim.launch.py profile:=record
ros2 launch uv_sim_bringup hil.launch.py profile:=record

# 调试：AI + 未标注 go2rtc 视频 + rosbag/session 日志
ros2 launch uv_bringup real.launch.py profile:=debug
ros2 launch uv_sim_bringup sim.launch.py profile:=debug
ros2 launch uv_sim_bringup hil.launch.py profile:=debug

# 一键运行默认 Mission；也可附加 mission_file:=/path/to/mission.yaml
ros2 launch uv_bringup real.launch.py profile:=task
ros2 launch uv_sim_bringup sim.launch.py profile:=task
ros2 launch uv_sim_bringup hil.launch.py profile:=task
\end{lstlisting}

\begin{warningbox}
\code{profile:=task} 会自动开始 Mission，不只是启动一个空闲的任务节点。真机入口同时启用运动控制；使用前应确认车辆处于允许运动的安全环境，并检查实际传入的 \code{mission_file}。
\end{warningbox}
\section{启动顺序与就绪}
典型依赖顺序是：描述/固定 TF、硬件或仿真输入、定位、控制、相机/感知、规划、任务。常规启动默认不执行任务；选择 \code{profile:=task} 时会启用任务执行器并自动开始默认 Mission。\pkg{uv_bringup} 提供 readiness 检查，可按 backend、control、sensors、perception 阶段确认 Topic 和节点已达到运行条件。

\section{参数事实来源}
整机启动 profile 设置 launch 开关和录制参数的默认值；组件参数采用各包默认值，可由支持 \code{params_file} 的 launch 显式覆盖；Mission/Task 参数保存在任务 YAML。相机的 real/sim 模式和内参保存在 \code{uv_camera/stereos/} 中，场景由 \code{uv_sim} 的 \code{world} 选择。参数优先级和最终生效值应通过启动日志或 ROS 参数查询确认；LaTeX 不复制完整参数树，附录只列出入口和语义。
