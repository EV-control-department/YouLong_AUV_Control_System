## 1. T1：仿真传感器对齐实机

### 问题

`xunyun_fixed.scn` 的 DVL 安装与实机不符，导致 `/auv/dvl` 发布的不是机体系速度：

| 项 | 旧值 | 后果 |
|---|---|---|
| DVL `<origin>` | `rpy=(3.1416 0 -0.785)` `xyz=(-0.375 0 0.2)` | 速度落在相对机体系旋转 45°、且 y/z 翻转的系里 |
| `<specs>` | `beam_angle="30.0"`，`beam_positive_z` 缺省 = false | 波束朝上，靠 180° 翻滚补偿 → 速度系 y/z 反 |

净效果：`basic_motion` 看到的沿航向速度成了 `V·cos(2α+45°)`——
**α=22.5° 时恒为 0**（航向与运动方向成 22.5° 就完全不前进）。

### 改动

| 传感器 | 改动 | 依据 |
|---|---|---|
| DVL | `rpy="0 0 0"`、`xyz="-0.375 0 0.1"`、`beam_angle="30.0" beam_positive_z="true"` | 实机：yaw=0 安装、波束斜置 45°、离竖直 30°、z≈+0.1 m |
| IMU | 20 Hz → **200 Hz**，注入噪声 `angular_velocity=0.0141` `linear_acceleration=0.1414` | σ = 噪声密度 × √rate，对齐 AQUA-SLAM 的 `NoiseGyro=1e-3` / `NoiseAcc=1e-2` |
| 前视双目 | 10 Hz → **20 Hz** | 与 SLAM 设置文件 `Camera.fps: 20` 一致 |
| 下视双目 / 里程计 / 压力 | 不变（30/30/5 Hz） | — |

同时修正 `/auv/odometry` 的 twist：`nav_msgs/Odometry` 的 `pose` 在 `header.frame_id`
（`world_ned`）、`twist` 在 `child_frame_id`（机体系），Stonefish 已按此发布；
旧代码又乘了一次 yaw（等价 `R(-ψ)`），ψ=90° 时纯前进 `u` 变成 `(0,-u)`。
现在只保留一个编码点 `sim_bridge.body_twist_from_odometry()`。

### 验证

- `workspace_sim/src/uv_sim/test/test_scene_sensors.py`（11 例）钉住场景契约；
- `workspace_sim/tools/check_dvl_frame.py`（在线端到端）设计成**修复前必失败**：
  在 ψ=0/22.5/45/90° 四段航向上比对 `/auv/dvl` 与 `v_odom_body + ω×r_dvl`，
  22.5° 那段是判别力最强的（旧配置下恒为 0）；
- 本机沙箱无 GPU/`/dev/dri`，GPU 版模拟器起不来，端到端待桌面会话执行（见 §6）。

## 2. PID 参数外置为单一事实源

### 问题：四套参数，只有一套真生效

| # | 位置 | 是否生效 | 说明 |
|---|---|---|---|
| 1a | `_init_full()` 的 `_pid_params` 字典 | ❌ 仅服务读写 | `/zit6/get_params` 返回它 → **报告值与实际不符** |
| 1b | 同函数的 `_Pid(...)` 对象 | ✅ 真正生效 | 控制回路唯一使用者 |
| 2 | `uv_hm/config/pid_params.yaml` | ❌ 无人读取 | 自称「sim_bridge 默认参数」，实为 1a 的旧快照 |
| 3 | `uv_hm/config/pid_parameters.json` | ❌ 无人读取 | MCU/AGX 的另一套体系（8 轴） |
| 4 | 固件 `UserApp/Config/config.json` | 实机生效 | MCU 自己的归一化参数化 |

实测漂移：`pos.z.ki` 报 30 实为 80、`vel.x.kp` 报 300 实为 600；
yaw 串级内环 `pid_yaw_rate` **既不在字典也不在服务面**（读不到也调不了）；
`/zit6/update_params` 的部分更新会用过期字典值回写对象的其它增益。

### 方案

新增 `workspace_sim/src/uv_sim/config/sim_pid.yaml` 作为唯一事实源（9 通道），
**同一份数据同时构造服务视图与 `_Pid` 对象**，二者不可能再漂移：

```yaml
chassis.pid.pos.{x,y,z,yaw}         # 位置模式：x/y/z 单环 + yaw 两级串级
chassis.pid.pos.yaw_rate            # 串级内环（此前服务面缺失）
chassis.pid.vel.{x,y,z,yaw}         # 速度模式：四个单环
```

- 加载顺序：`-p pid_config_file:=<path>` > 源码树 > 安装 share > 内置回退（打 WARNING）
- `/zit6/update_params` 仍只改运行时，**不写回文件**
- 删除死文件 `uv_hm/config/pid_params.yaml` 及其安装项

**澄清一个常见误解**：并非全轴串级。位置模式的 x/y/z 是**单环**（位置误差→力），
只有 **yaw 是两级串级**（角度误差→目标角速度，±45°/s 限幅→与陀螺角速度之差→力矩）；
速度模式是四个单环。

## 3. T2：坐标系与外参基线

### 交付物

| 文件 | 作用 |
|---|---|
| `docs/frames/frame_convention.md` | **约定的唯一权威**：四套坐标系、单位分界、rpy 顺序、TF 现状、odom 系、相机光学系、`type_mask` 反逻辑；每条带「文件+符号」锚点 |
| `docs/frames/extrinsics_reference.md` | **数值的唯一权威**：仿真表/实机表/`T_b_c`·`T_gyro_c`·`T_dvl_c` 推导/与 AQUA-SLAM `Tbc` 逐元素对照/α 敏感度/T6 必改清单；含机器可读 YAML 块 |
| `uv_sim/geometry.py` | 几何唯一真相点（纯 numpy，无 ROS） |
| `tools/derive_extrinsics.py` | 从 `.scn` 推导外参；`--check` 与文档对拍，漂移即非 0 退出 |
| `tools/check_dvl_geometry.py` | 波束几何数值校验 + α 敏感度表 |
| `tools/dump_tf_tree.py` | 在线 TF 核对 + `--self-test` |
| `config/extrinsics/xunyun.yaml` | 机器可读外参表（生成物，禁止手改） |

### 关键概念：θ 与 α 是两个不同的角

| 记号 | 含义 | 值 |
|---|---|---|
| **θ** | 波束离**竖直**轴（场景 `<specs beam_angle>`，单位**度**） | 30° |
| **α** | 波束离**水平面**（AQUA-SLAM `mE`，单位弧度） | **60° = 90° − θ** |
| **β** | 波束方位角 | 45/135/225/315° |
| **ψ** | 艇的航向（历史代码里被误叫 `alpha`，已改名） | — |

AQUA-SLAM 出厂设置里 `alpha = 1.1780 rad = 67.5°`（blue_gx5 平台），
**用错会让水平速度整体偏 +30.66%**（`cos67.5/cos60 = 1.3066`），垂直只偏 −6.3%。
把 θ 当 α 填则是 −42%。这类错误在仿真里**永远自洽**（用 α 合成波束、再用 α 反解），
只有实机数据才暴露——所以它是 T6 移植的头号风险项，已列成必改清单。

**与 AQUA-SLAM 记号的对照**（两个独立来源给出同一矩阵，证明没搞反）：
其 yaml 的 `Tbc` 平移列 `(0.4, 0, 0.1)` = 相机在机体系的位置，旋转块
`[[0,-1,0],[0,0,-1],[1,0,0]]` 与本仓库 `T_b_c` 逐元素一致（差 1e-5 级舍入）。

## 4. 三个隐蔽不一致（本轮查出并修正）

### N1 相机 offset 差 0.2 m

| 位置 | z 值 |
|---|---|
| `position.py` `CAM_PARAMS` | 0.076 / 0.0645 |
| `line_follower.py`、`arrow_surfacer.py` `_DOWN_OFFSET_*` | 0.0645 |
| `docs/perception.md` | 0.076 / 0.0645 |
| `xunyun_fixed.scn` `<origin>` | ~~0.276 / 0.2645~~ |

四处代码/文档一致，场景是孤例 → **以代码为准，改场景**。该值直接决定射线原点
（多射线交会），错 0.2 m 会让下视斜射线落点偏移。

**残留下限**：这组数字本身仍来自早期估算（`devlog/2026-07-05_status.md` 记
「实车外参是否正确**未验证**」）。本次解决的是「代码与场景互相矛盾」，不是「数值经过实测」。

### B18 TF 从未开启，而文档断言它存在

`ROS2SimulationManager.cpp` 的 TF 广播套着 `if (publishBaseLinkTransform_)`，
该标志由 `<robot>` 的子元素 `<ros_base_link_transform publish=...>` 决定，默认 `false`；
本仓库 15 个 `.scn` **一个都没写** → **仿真完全没有 TF**（`/tf` 实测为空）。

T2 文档初稿误称「仿真里唯一的 TF：`world_ned → Vehicle/base_link`」，并把
`ROS2SimulationManager.cpp:395` 当证据（忽略了 `if` 守卫）。**是 `dump_tf_tree.py`
在线跑出 exit 1 才暴露的**——工具抓到了文档的错误。

顺带修掉一个连带 bug：工具原先硬编码期望帧名 `Vehicle`，而 canyon 场景通过
`<arg name="robot_name" value="XUNYUN"/>` 把艇命名为 `XUNYUN`，一开 TF 就会误报。

### PID 回退与文件不同步

见 §2。回退值（文件丢失/损坏时用）与调好的文件曾在两条 yaw 通道上差 23 倍
（`pos.yaw` kp 1.5 vs 35），丢文件会**静默**换一套转向控制器。
现已对齐 + 警告写明后果；测试只校验结构而不比对数值（否则每次调参都要改测试）。
