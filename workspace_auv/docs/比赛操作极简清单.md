# 比赛操作极简清单

任务入口：`workspace_auv/src/uv_task/config/missions/competition.yaml`。

顺序：START → 九宫格建图及反向巡检 → 撞转盘 → 海参抓取投放 → 靠岸。

## 1. 赛前测量并填写

所有任务坐标使用**同一次 START 后的 odom 原点**，米、角度；z 向下为正。先固定发车位置、姿态和深度基准，再测场地坐标。表中的文件均位于 `workspace_auv/src/`。

| 必须核对或实测的内容 | 填写位置与参数 |
|---|---|
| 九宫格中心、整体边长、旋转角、池底 z、巡检 z 和航向 | `uv_task/config/tasks/mapping_grid.json`：`grid_center_x/y`、`grid_side_m`、`grid_yaw_deg`、`floor_z`、`survey_z`、`survey_yaw_deg` |
| 标签位置、实际 ID、两个方形和两个圆形所在格点 | 同上：`tag_x/y`、`allowed_tag_ids`、`fallback_tag_id`、`fallback_square_cells`、`fallback_round_cells`。格点 ID 为 0～8；预设结果必须与实测布置对应 |
| 转盘盘心 x/y/z、正对盘面的艇体航向、相机到盘面的观察距离 | `uv_task/config/tasks/turntable_simple.yaml`：`disk_pose_odom`、`front_standoff_m`；联动修改任务链“转盘观察位”航点 |
| 转盘撞击速度、持续时间、居中误差是否允许前冲 | 同上：`charge_speed_mps`、`charge_duration`、`center_tolerance_fraction`。用水池录像确认实际接触，时间结束不代表转盘转动成功 |
| 海参搜索和投放艇体位姿、实际海参数量 | `uv_task/config/tasks/grab_sea_cucumber.yaml`：`search.pose`、`delivery.pose`、`expected_count`；联动修改任务链海参搜索终点 |
| 相机与夹爪水平偏置、投放偏置、抓放角度、机械等待时间 | 同上：`gripper.servo_id`、`gripper.offset_x_m/offset_y_m`、`gripper.contact_body_xyz`、`gripper.pickup_angle_deg`、`gripper.release_angle_deg`、`gripper.settle_seconds`、`gripper.close_wait_seconds`、`collection_release_offset_body_xy`；舵机2另测 `gripper.servo2` 安装坐标和角度 |
| 池底 z、艇底/夹爪最低点、近底切换净距、下压/离底推力与时长、实际上浮速度 | 同上：`floor_z_m`、`bottom_reference_offset_z_m`、`open_loop_clearance_m`、`press_thrust`、`lift_thrust`、`press_thrust_seconds`、`descent`、`ascent`。近底纯推力没有水平/姿态保持和触底停止反馈 |
| 下压前后是否发生真实水平位移 | 同上：`restore_pre_press_odom_xy`。当前为 true，会假定 XY 差是漂移并校正；不能把真实位移当导航漂移 |
| 三段转场的绕障点、终点、通道净距；返航折点、靠岸点和正对岸航向 | `uv_task/config/missions/competition.yaml`：各 `world_waypoints.waypoints`、`runtime.return_waypoint_xy`、`return_shore.x/y/yaw_deg`。分段直线不会自动避障 |
| 靠岸前推/上浮推力及持续时间、保持整艇浸没的结束 z | 同上：`return_shore.forward_thrust/forward_seconds/lift_thrust/lift_seconds`、`runtime.surface_z_m`。当前靠岸四项均为 0，只到准备点，不执行完整靠岸 |
| 前/下视设备编号、安装方向、双目标定、相机外参、模型类别 | `uv_camera/config/profiles/real_default.yaml`：`front_cam_path`、`down_cam_path`、旋转参数、`mapping_calibration_file`、相机安装平移/旋转；模型映射见 `uv_camera/weights/real_last.yaml`。核对转盘、海参、收集框类别 |

池底参数 `floor_z` 与 `floor_z_m` 必须使用同一深度基准；不同作业区深度不同则分别实测。机体系偏置为 x 前、y 右、z 下。推力是归一化数值，不能当作 m/s。

任务链覆盖参数优先：当前海参总预算 **360秒**；总计时 **840秒** 后抢占，取消旧动作、返原点和上浮共用 **60秒**。上浮结束深度必须满足比赛全程潜水要求。

修改配置后重启对应节点。若安装时未用 `--symlink-install`，还需重新构建对应包；任务命令使用源码任务链的绝对路径。

## 2. 开哪些节点

| 启动项 | 用途 | 启动方式 |
|---|---|---|
| micro-ROS 串口 Agent | 与主控板通信 | 终端1单独启动 |
| `hw_manager` | 主控状态监控 | 终端2统一启动 |
| `basic_motion` | 运动服务、位姿、START 后心跳 | 同上 |
| `uv_camera` | 前/下视检测、建图观测、视频流 | 同上，前/下视均开启 |
| `object_localizer` | 常规目标定位 | 同上，由真机入口自动启动 |
| `uv_record` 录制进程 | 保存视频、地图、任务和轨迹 | 终端3启动 |
| `task_runner` | 执行比赛任务链 | 终端4最后启动，立即发车 |

当前比赛链直接调用运动接口，下面关闭 `navigator`。不要重复启动同名节点，不要另外开启 GUI/硬件监控节点的心跳发送。

## 3. 按顺序执行命令

每个终端先执行一次环境准备。以下是当前电脑路径；艇上只需改仓库目录及 ROS 版本（如 Foxy），所有终端使用同一 ROS 环境和 DDS domain。

```bash
cd /home/laurie/AUV_2026_Robocup/YouLong_AUV_Control_System
source /opt/ros/humble/setup.bash
source workspace_auv/install/setup.bash
```

**终端1：通信。** 串口和波特率须与当前主控固件一致。

```bash
MicroXRCEAgent serial --dev /dev/ttyUSB0 -b 921600
```

若艇上安装的是 ROS 包版 Agent，改用以下命令，二选一：

```bash
source ~/micro_ros_agent_ws/install/setup.bash
ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyUSB0 -b 921600
```

**终端2：控制、监控、感知。此时不开任务。**

```bash
ros2 launch uv_bringup real.launch.py profile:=real_default \
  enable_task:=false enable_nav:=false enable_ai:=true turntable_mode:=false
```

`turntable_mode` 保持 false；true 会关闭下视与建图视觉，不适用于完整比赛链。

**终端3：录制。** 确认前视、下视均已实际写入视频，再发车。

```bash
ros2 run uv_record record --profile competition \
  --output-root "$PWD/records/sessions"
```

**终端4：发车前检查。**

```bash
ros2 node list
ros2 topic echo /zit6/state/status --once
ros2 topic hz /zit6/state/odom
```

确认 `navigation_ready: true`、无故障、odom 持续更新；频率检查后 Ctrl-C。确认双摄画面、类别与测量配置无误。START 前未建立任务原点属于正常启动阶段。

**终端4：最后发车。启动即执行，无拔缆倒计时。**

```bash
ros2 launch uv_task task_launch.py \
  mission_file:="$PWD/workspace_auv/src/uv_task/config/missions/competition.yaml"
```

发车后可用其他终端检查 `ros2 topic hz /basic_motion/pose_info` 和 `ros2 topic echo /task/status`。正常比赛期间保持自主执行。

**停止命令：**

```bash
ros2 service call /task/stop std_srvs/srv/Trigger '{}'
```

停止会取消普通任务并持续零推力；重新发车需要重启 `task_runner`。

## 4. 结束后处理建图结果

**先停运动，再保存结果，最后关闭节点。** 保持 `task_runner` 和录制器运行，先执行上面的停止命令。不要先重启任务：新一轮会清除上一轮结论 ready 状态。

在同一个终端执行下列命令，创建本轮结果目录并保存最终话题和配置：

```bash
RUN_EXPORT="$PWD/records/competition_result_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$RUN_EXPORT"
timeout 10s ros2 topic echo /task/mapping/map --once \
  --qos-durability transient_local --qos-reliability reliable \
  > "$RUN_EXPORT/map.yaml"
timeout 10s ros2 topic echo /task/mapping/conclusion --once \
  --qos-durability transient_local --qos-reliability reliable \
  > "$RUN_EXPORT/conclusion.yaml"
cp -r workspace_auv/src/uv_task/config "$RUN_EXPORT/task_config"
cp workspace_auv/src/uv_camera/config/profiles/real_default.yaml \
  "$RUN_EXPORT/camera_real_default.yaml"
```

两个 YAML 的 `data` 字段内是 JSON。检查文件非空；超时或没有内容时，从本轮录制 session 的 `metadata/mapping.jsonl` 和 `bag/` 查找结果，不将空文件当成功。

只核对三件事：

1. **路线完成情况：** 地图的 `visit_order`、`traversal_order`、`travel_failures`。当前首圈 `8→7→6→3→4→5→2→1→0`，反向 `0→1→2→5→4→3→6→7→8→标签点`。尝试过不等于实际到达；`ready=true` 不代表第二圈完成。
2. **视觉结果：** 地图的 `cells`、`final_assignment`、`tag`、`source`、`accepted_observations`、`verified_complete`。保留未知和失败记录，不把预设填充值当视觉测量。
3. **预设结论：** `/task/mapping/conclusion` 当前固定取配置值，`source=fallback`、`verified=false`。`ready=true` 且 `valid=true` 只表示预设数据可读且格式有效；当前配置为方形 `[0,8]`、圆形 `[5,6]`、标签16，须现场核对。

保存后，录制终端 Ctrl-C 并等待收尾完成，再关闭任务、控制/感知和 Agent；确认主控锁定后断推进供电、回收。将**完整 session 文件夹、结果目录、当轮场地记录**一起备份，不只保留地图截图。

需要图和报告时，填本轮实际 session 路径；报告目录须新建且在 session 外：

```bash
ros2 run uv_record analyze /绝对路径/本轮session \
  --output /绝对路径/本轮新报告目录
```

查看 `report.html`；保留 `maps.json`、地图 SVG/CSV 和原始 session。对外提供格点 ID、类别、原始 `[x,y,z]`、标签 ID，并注明视觉/预设来源及巡检是否完成。显示时的 XY 交换不改变提交坐标。现有代码未提供可确认的官方上传协议，因此这里只准备结果文件，按赛方格式另行提交。
