# 前视逐门过门任务

订阅 `/auv/perception/detections` 的 `front_left` / `front_right`，只使用
`gate_front` 检测、相机标定/外参和实测 odom。角度为度，z 正向向下。

## 当前门框选择

每只眼只保留最新一条检测消息的所有有效框，新消息无门框时立即清除该眼候选。
在两眼的当前有效框中选择 **bbox 高度占单目画面高度比例最大** 的框；
高度相同时比较面积，再比较消息新旧。观测超过 `search.detection_timeout` 后失效。
检测仍须满足置信度、最小 bbox 尺寸和几何有效性要求。

不创建门框 ID、不关联轨迹、不固定主相机、不要求连续三帧确认，也不重获旧目标。
左右眼可以随当前最大框直接切换。旧 `tracking`、相机优先权、重获和双目关联参数
仍可被配置解析器接受，但不再参与过门运行；任务 YAML 已移除这些参数。

## 每门执行顺序

1. 第一门 SET 到对应的完整 `[x,y,z,yaw]`。上一门穿门完成后，先保持
   BLINE 终点原地观察下一门 2 秒；看到当前有效门框则直接对准，没看到才 SET
   到下一条预设位姿。上一门失败并跳过时直接 SET 到下一条预设位姿。
2. 到预设位姿后保持 XY 和配置深度观察 2 秒。没有框时保持 XY 右扫最多 90°，
   再 SET 返回观测位姿并左扫最多 90°。扫描中一旦看到框就停止扫描，使用当前最大框。
3. 将最大框中心的相机射线通过外参和实测姿态变换到世界系，直接 SET 航向对准。
   看到最大框并完成这次对准后，即满足本门的视觉成功条件；之后不要求再看到同一门。
4. 沿当前机头方向单次 BLINE 前进最多 **0.3 m**，巡航速度沿用 YAML 的 **0.25 m/s**。
   行进中只检查两眼所有当前有效观测中的最大框高，**严格大于画面高度的 80%**
   就取消 BLINE，并等待动作终态确认停止。开始时已超过阈值则跳过近距前进。
   没超过阈值就走完 0.3 m；途中丢框继续运动，不停车等待重获。
5. 停车后若有当前门框，保持 XY/深度并尝试 yaw 对准当前最大框，最多 3 秒。
   误差在 2° 内连续稳定 0.3 秒，且总时长至少 1 秒时结束。没有框、途中丢框，
   或时限内未稳定，均停止转向并直接 pass；不因这些视觉条件失败而跳门。
6. 沿停车/再次对准后的当前机头方向执行 **1.0 m BLINE pass**，速度 **0.2 m/s**，
   不要求新帧或门框关联。动作完成后计入通过数量，使用 `final_target` 同步指令位姿。

框高比例为裁剪后的 bbox 高度除以所属单目画面高度，**80% 不表示机器人深度 0.8 m**。
观测深度仍使用对应 `observation.poses` 的 z，并贯穿该门的观察、对准和穿越。

## 主要参数

```yaml
gate_count: 4          # 执行 observation.poses 的前 1–4 条
timeout: 720.0         # 每门重新计时
max_failures: 2        # 允许失败后跳到下一门的次数
observation:
  poses:              # 每门 odom 绝对 [x,y,z,yaw]，实际值见任务 YAML
    - [1.8, 0.3, 0.4, 90.0]
    - [1.8, 2.0, 0.18, 90.0]
    - [1.9, 2.9, 0.18, 90.0]
    - [1.7, 4.2, 0.4, 90.0]
  set_timeout: 20.0
fore_aft:
  height_limit_percent: 80.0
  max_distance_m: 0.30
  speed_mps: 0.25
  position_tolerance_m: 0.01
  timeout: 30.0
pass:
  distance_m: 1.0
  speed_mps: 0.2
  timeout: 20.0
  next_observe_seconds: 2.0
  pause_seconds: 0.5  # 最后一门穿越后的停顿
```

`poses` 最多四条，数量不能少于 `gate_count`。每条 z 独立配置。
左右扫描和最终 yaw 期间使用 `search.position_hold_*` 保持世界 XY。
BLINE 运动、门间原地观察和最后停顿期间不发送视觉伺服速度。

## 动作失败与交接

没有找到初始门框、初次 SET 对准失败、BLINE 动作失败、无有效定位或单门总超时，
仍按失败策略处理。单门失败先确认旧动作取消终态、零速度和停车，无法确认则禁止
进入下一门。最后一门失败返回任务失败；其他门可按 `max_failures` 跳过。

共享动作接口在定位动作超时后使用独立的至少 2 秒预算确认取消完成，再允许下发
下一条定位。取消响应本身不算动作终态；迟到的目标接受响应也会取消。
无法确认旧动作结束时保留记录并停止任务列表，避免下一条定位被占用中的服务器拒绝。

部署前重新构建 `uv_task`，加载对应安装环境并重启 `task_runner`。
