# 前视过门任务

`26rb_gate_task.py` 直接订阅 `/auv/perception/detections`，读取
`front_left` / `front_right` 的 `gate_front` 检测，不依赖目标定位器话题。
射线使用前视单目内参、畸变和相机 TF 外参；运动反馈来自任务执行器的实测 odom。

## 执行顺序

每个门：定深 → 观察 2 秒／扫视 → 单目对准 → 配置横移 → 观察 1 秒并对准
→ 等待转向后的新帧并记录固定世界水平射线 → 面积控制 → 最终 yaw → BLINE。
四门默认水深均为 0.1 m，横移均为 0 m，任务总超时 720 s。

- 有效新帧先到的一目获得控制权；另一目继续缓存检测。
- 当前目丢框时立即停止水平移动并保持水深。最后有效帧之后超过 2 s 释放控制权；
  只有释放后收到的新帧可以重新获得控制权，原目也能再次获权。
- 检测新鲜度默认 1.5 s，包含接收年龄和消息时间戳年龄；有 `capture_id` 时去除重复帧。
- 门框没有目标 track ID，因此同一门通过几何射线、已重建中心的重投影和图像中心连续性关联。
  关联不通过时按丢框处理，不选更大的相邻门。关联容限在 `search` 中配置。
- 切目不重置横移起点、横移方向、已完成位移或前后固定射线；面积稳定时间重新计算。
- 所有速度阶段用实际深度误差产生世界 z 补偿，再用完整 roll/pitch/yaw 转到机体系。
  丢框期间的机体系 x/y 分量可能不为零：倾斜姿态下它们共同产生纯世界垂向补偿。

## 五组 YAML 参数

文件：`config/tasks/26rb_gate_task.yaml`。

| 组 | 设置 |
|---|---|
| `depth` | 四位门深数组（z 向下，米），定深超时、深度增益、垂向限速和深度容限 |
| `search` | 观察时长、-30° 起点、60/120/180° 扫描、10°/s、置信度、新鲜度、优先权释放与重获、普通对准、闪灯 |
| `lateral` | 四位有符号横移数组，0.05 m/s、0.02 m 容限、40 s；实测 odom 沿起点机体 y 投影计进度 |
| `fore_aft` | 80% 框面积，1 个百分点容限，稳定 0.5 s；正反限速 0.10/0.08 m/s，位移上限 4 m、90 s |
| `pass` | 最终 yaw 的 1–3 s、2°/0.3 s 条件，双目配对与几何检查，BLINE 距离/速度/超时，完成停顿 |

面积 = bbox 裁剪到单目画面后的面积 / 单目画面面积 × 100；不使用框宽高比。
前后沿记录射线的水平投影运动，并修正横向偏离。超时或超出位移上限会停车退出，
不会把不可达面积当作成功。

## 最终 yaw 和动作交接

双目优先按非零 `stereo_pair_id` 配对；任一 ID 缺失时按消息时间戳配对。
检查配对时差、射线夹角、前向距离、两射线最短距离、框大小一致性与门身份。
有效双目用两射线的最近点中点重建中心，再计算它相对机体中心的世界偏航角；
不满足条件时用当前优先目。双目参与不改变相机优先权。

满 1 s 后误差在 2° 内连续稳定 0.3 s 可以完成；到 3 s 只要观测仍有效，
即使误差未达标也按实测航向继续，并记录剩余误差。切目不延长这个预算。
观测在结束或交接时丢失则不发 BLINE。

先确认零速度动作完成，再发送 BLINE。BLINE 执行及成功后的 0.5 s 停顿期间，
任务不再发送旧 yaw/深度速度。默认目标为 `[1.6, 0, 目标深度-当前深度, 0]`，
`axes=xyz`，速度 0.15 m/s，超时 60 s；成功后用 `final_target` 同步指令位姿。
整个任务截止时间会限制阶段和动作等待；超时取消已接受或延迟接受的动作。
失败停车允许额外的有界清理时间，未确认的速度输出由租约到期停止。
搜索失败的两次红灯闪烁由任务执行器保留。

## 构建和验收

```bash
source /opt/ros/jazzy/setup.bash
colcon build --packages-up-to uv_task uv_control --symlink-install
source install/setup.bash
python3 -m pytest -p no:cacheprovider \
  src/uv_task/test/test_26rb_gate_task.py \
  src/uv_task/test/test_gate_action_handoff.py \
  src/uv_task/test/test_bline.py
```

必须同时构建并加载包含 `BLINE=8`、`cruise_speed` 与 `final_target` 的 `uv_msgs`，
以及使用该接口的控制和任务包；不能让节点继续使用旧 overlay 的 Action 类型。
行为测试使用虚拟位姿和时钟。真实 Action 集成测试使用独立 ROS 域 184 的合成后端，
不驱动实艇；测试文件为 `uv_control/test/test_line_ros_integration.py`。
原 `.py.bak` 与 `.yaml.bak` 保留。
